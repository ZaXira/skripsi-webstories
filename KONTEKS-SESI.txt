7.4  Optimasi gambar — keputusan penting
     PNG asli 3574x1339 RGBA, ~3,5 MB/file, total ~13,6 MB. Terlalu berat.

     Disajikan lewat <picture>: browser modern ambil .webp, sisanya .jpg.
     .jpg sengaja dipertahankan sebagai jaring pengaman kalau halaman
     dibuka di mesin asing saat sidang.
     PNG resolusi penuh TETAP UTUH di Tujuan 3/tujuan3_overlay/.
     Skrip regenerasi ada di README.md bagian "Menambah Aset Visual".

     disisipkan SETELAH .tile-wrap dan SEBELUM .oracle.
     Caption memakai angka yang SUDAH ADA di tabel tile (jumlah poligon GT,
     F1 lokalisasi, akurasi klasifikasi) — sengaja tidak memperkenalkan
     angka baru apa pun.
     CATATAN: judul panel di dalam gambar memuat "n=" hasil prediksi yang

     tabel Pred.=107). Perhitungannya memang beda. JANGAN "diselaraskan".

7.6  Lightbox overlay
     Alasan: 3 panel pada lebar ~500 px tidak terbaca. Klik gambar ->
     pratinjau besar. Tutup via klik, tombol x, atau Esc.
     Sempat ada tabrakan z-index: .theme-btn (300) dan .prog-nav (200)
     menutupi lightbox. Solusi: .lb dinaikkan ke z-index 400, plus class
     body.lb-open yang menyembunyikan keduanya selama lightbox terbuka.
     Token baru di :root: --lb-scrim, --lb-fg (sengaja theme-independent).

7.7  Tujuan 3/ dikecualikan dari deploy — dua lapis
     (a) .gitignore  -> tidak pernah masuk repo
     (b) deploy.yml step "Stage site" -> tidak masuk artefak Pages
     Ukuran folder itu ~49 MB, termasuk zip 14 MB.

7.8  vercel.json
     /img/* sebelumnya disajikan "max-age=0, must-revalidate" (default
     Vercel) sehingga setiap kunjungan ulang menembak server lagi.
     Sekarang "public, max-age=86400, stale-while-revalidate=604800".

7.9  BUG DEEP-LINK — ditemukan dan diperbaiki (commit 0f48e4e)
     Gejala : buka .../#s6 langsung -> mendarat di posisi salah, section
              tampil KOSONG sampai user scroll manual.
     Sebab  : font Google + canvas Chart.js menggeser layout SETELAH load,
              jadi lompatan hash bawaan browser meleset; setelah itu
              IntersectionObserver tidak pernah menyala untuk .rv di situ.
     Perbaikan di komponen SCROLL REVEAL:
       - rvSweep(): menandai .in pada semua .rv yang sudah di viewport,
         dipanggil pada 'load' dan setTimeout 500 ms
       - kalau ada location.hash: reposisi ulang pada 'load' (80 ms dan
         600 ms), dengan scroll-behavior di-set 'auto' SEMENTARA lalu
         dikembalikan
     JEBAKAN yang ditemui saat memperbaiki:
       html { scroll-behavior: smooth; } ada di CSS. Memanggil
       scrollIntoView({behavior:'auto'}) TIDAK cukup — 'auto' berarti
       "ikuti nilai CSS", jadi tetap smooth. Harus override properti
       scroll-behavior elemen root, itulah sebabnya kodenya terlihat
       berbelit.

7.10 Keamanan — token GitHub
     Remote origin dulu berbentuk https://ZaXira:ghp_...@github.com/...

     Sudah dibersihkan: remote kini https://github.com/ZaXira/skripsi-webstories.git

9. CARA MENGUJI PERUBAHAN (resep yang sudah terbukti jalan di mesin ini)
================================================================================

Chrome ada di:  $LOCALAPPDATA/Google/Chrome/Application/chrome.exe
                (BUKAN di "C:/Program Files/..." — sudah dicek, tidak ada)
Python + Pillow 10.3.0 tersedia. ImageMagick TIDAK ada.

Server lokal:
    python -m http.server 8099

Screenshot section tertentu — elemen .rv default opacity:0, jadi untuk
screenshot statis buat salinan sementara dengan reveal dipaksa:
    .rv { opacity:1 !important; transform:none !important }

    chrome.exe --headless=new --disable-gpu --hide-scrollbars \
      --window-size=1440,2600 --virtual-time-budget=12000 \
      --screenshot=out.png "http://localhost:8099/_tmp.html"

Memeriksa perilaku runtime (lebih andal daripada screenshot):
    chrome.exe --headless=new --disable-gpu --virtual-time-budget=20000 \
      --dump-dom "https://skripsi-webstories.vercel.app/#s6" \
      | grep -o 'class="overlay-grid[^"]*"'
    -> harus memuat " in" kalau reveal bekerja

JEBAKAN PENGUJIAN HEADLESS (penting, sudah menghabiskan waktu):
  a) --screenshot + --virtual-time-budget membekukan transisi CSS di tengah
     jalan. Section bisa terlihat KOSONG di screenshot padahal class .in
     sudah terpasang dengan benar. Untuk memverifikasi reveal, baca DOM
     (--dump-dom) atau getComputedStyle, JANGAN percaya screenshot.
  b) Chrome di Windows punya lebar jendela minimum ~485 px. --window-size=390
     tetap menghasilkan viewport 485 px lalu gambarnya dipotong ke 390 —
     terlihat seperti overflow horizontal padahal bukan. Untuk uji mobile
     sungguhan, pakai emulasi devtools, bukan --window-size kecil.

    - semua angka di bagian 8 masih ada
